## Retrospective

### Keep (ทำดี ทำต่อ)

- แบ่งงานตาม layer (DB, DAO, API, UI, QA) ชัดเจน ทุกคนมี Task ของตัวเองบน Trello
- ใช้ Docker compose ทำให้ทุกเครื่อง (Windows / Mac) รันระบบเหมือนกัน
- มี test ครบทุกระดับ พร้อมรูปหลักฐาน

### Problem (ปัญหา)

- PR ใหญ่และ merge ช้า บาง PR ถูกปิดแล้วต้องเปิดใหม่ (#11, #12)
- รีวิว PR น้อย (Approve แค่บาง PR), มีการ push เข้า develop ตรงโดยไม่ผ่าน PR
- Docker Desktop บน Windows พังบ่อย (WSL / ไฟล์ image เสีย) เสียเวลาแก้เครื่อง
- ข้อมูลทดสอบเปลี่ยนหลายรอบ (พิกัดลาน) ทำให้ test spec / เอกสารต้องตามแก้
- งานไปกองช่วงท้าย Sprint

### Try (Sprint 2 จะลอง)

- เปิด branch protection ตั้งแต่วันแรก: ต้องผ่าน PR + Approve 1 คน
- PR เล็กลง merge ทุกวัน, Daily Scrum สั้นๆ ใน LINE ทุกเย็น
- เขียนผลทดสอบพร้อมกับโค้ดใน PR เดียวกัน
- ล็อกข้อมูลทดสอบ (ตำแหน่ง / ลาน) ก่อนเริ่มเขียน test spec
